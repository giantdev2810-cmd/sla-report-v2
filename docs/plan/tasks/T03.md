## Walkthrough and review points

For each GET, `Inspection.get` first writes the safe attempt output, then saves
the body as bytes and metadata after the response returns, before examining status
or JSON. For example, a mocked 500 HTML response remains unchanged in its `.body`
file, records status 500 in metadata, and stops without another request. The real
run received only 200s. Metadata's cursor_supplied flag preserves traversal context
without duplicating the cursor value outside raw bodies.

In the actual run, requests_page_1 and requests_page_2 enable an offline ID-set
comparison; only the overlap count is printed. The selected event list ends at
page 1, so the run finishes at eleven rather than twelve requests. Later sessions
can inspect the retained local bodies instead of calling the API again. Empty
all() checks must be read with sample sizes, and local raw files are not replicated
through the public PR. If storage fails, even the final failure record may be
unwritable; the script stops and prints a safe fallback rather than making more GETs.

Review Capture for write ordering, Inspection.get for request bounds/error paths,
and the tests for evidence-retention guarantees. Application behavior is unchanged.
